## What this PR does

A complete redesign of the **super admin** panel (Optibiz design language — navy `#0f2438`, lime `#c2f542`), plus the **verification harness** that proves it works, and a **merge of `main`** that keeps the author's newer admin panel while removing four hardcoded password bypasses.

### 🔒 Security: four hardcoded password bypasses removed

`29f6bf0` ("fix the index appearance") — the current tip of `main` — added code that signs *anyone* in without knowing a real password, on both login forms:

```php
// superadmin/login.php
if ($password === 'password' || $password === 'superadmin123') { …sign in as super admin id 1… }
// admin/login.php
if ($password === 'admin123') { …sign in as the first admin of a tenant… }
```

Concretely, with that code on `main`:

| Attempt | Result on `main` | Result on this branch |
|---|---|---|
| `superadmin` / `password` | **signed in as the super admin** | refused — "Invalid username or password" |
| any username / `admin123` | **signed in as an admin of a tenant whose subscription is `cancelled`**, with that tenant's real password disabled | refused |
| `tamale_admin` / `admin123` | signed in | refused |
| `tamale_admin` / `tamale-solar-2026` (its own password) | signed in | signed in |

Those bypasses are removed here. Real credentials only — exactly as the rest of the codebase already behaved. Everything else from that commit is kept: the email-or-username lookup, the password reset link on both forms, the tenant login link, and the session helpers (`isLoggedIn`, `isTenant`, `isAdmin`, `getTenantId`, `getCurrentUserName`).

### Merge decisions

1. **`admin/` takes the author's newer restyle wholesale.** The redesign showed that a bare `__DIR__` in a subdirectory page resolves to `admin/` and makes every `require_once` fail — the author's commit shipped exactly that, so the include paths are corrected to `dirname(__DIR__)`. The theme toggle on `admin/login.php` is dropped because admin pages do not load `superadmin.css`.
2. **`includes/header.php` keeps both sides.** The author's `$assetBase` now derives from `$BASE`, so it produces `../assets/…` for subdirectory pages *and* `/assets/…` for root pages, rather than relying on `DOCUMENT_ROOT`. The super admin's own base path and theme bootstrap stay.
3. **The robots meta is opt-in.** The author's version hardcoded `noindex, nofollow` for *every* page, which would keep the public landing page out of search indexes. It is now a `$robots` variable, set by all 14 superadmin and admin pages and left unset by the public ones.

### The redesign itself

All 8 superadmin pages rebuilt in the existing design language, with charts drawn as inline SVG, a dark/light theme persisted in `localStorage` (a pre-paint bootstrap avoids a white flash), and content sourced from the existing tables only.

| Page | What is on it now |
|---|---|
| `index.php` | 5 live KPIs (12-month trend sparklines), revenue trend chart, tenant growth, subscription status donut, plans leaderboard, latest signups, subscriptions expiring within 30 days (grouped `overdue → 7 days → 14 days → 30 days`), newest quote requests |
| `tenants.php` | searchable + sortable roster, filters, bulk suspend/activate/delete, add-tenant dialog |
| `tenant_details.php` | per-tenant metrics, status timeline, revenue, plan, users, subscriptions |
| `plans.php` | plan cards with price, features, tenant counts |
| `subscriptions.php` | filters, status pills, revenue KPIs |
| `quote_requests.php` | request queue, status filters, reply dialogs |
| `analytics.php` | growth chart, status breakdown, monthly revenue, heatmap |
| `settings.php` | profile, password change, CSRF-protected |

Helpers live in `includes/sa_helpers.php`; markup comes from the existing `_shell.php` / `_shell_footer.php`. All 22 authenticated POST forms carry `sa_csrf_field()` and are validated by `sa_csrf_ok()`.

### Verification harness (`tools/`)

The sandbox has no browser, no database and no running PHP server, so the pages are exercised with the real PHP binary instead:

```bash
node tools/test-all.js     # all six checks, ~100 s
```

| Check | What it proves |
|---|---|
| `render-php-preview.js` | Every superadmin page renders from the real PHP source with zero warnings; 25/25 POST handlers; 6 edge-case probes; a fresh install with an empty database; anonymous access to all 8 pages redirects |
| `check-browser.js` | Each rendered page loaded in jsdom with the real `superadmin.js`: theme toggle persists, sidebar collapse, table filtering, column sorting and `aria-sort` |
| `check-other-pages.js` | Admin panel renders, both panels stay isolated, both login forms accept real credentials and refuse the bypasses, all 5 public APIs |
| `check-css.js` | Parses the rendered HTML and every stylesheet: no undefined CSS variables, no unstyled classes |
| `check-a11y.js` | Landmarks, one `h1` per page, heading order, image `alt`, control labels, form validation, table semantics, focus styles, `<meta name="robots">` on non-public pages |
| `check-sql.js` | Every table and column the PHP reads or writes exists in `database.sql` |

To render or browse the panels yourself:

```bash
node tools/preview-server.js 4173    # http://127.0.0.1:4173/superadmin/
```

### One bug found and fixed along the way

`includes/header.php` carried a `//` comment containing a literal `?>`. PHP ends the code block on that sequence *even inside a comment*, so `$assetBase` was never assigned and raw PHP leaked into the output. The comment is reworded, and `check-other-pages.js` now fails if any comment in `includes/`, `admin/` or `superadmin/` contains `?>`.
